# Hopa Pizza — موقع المتجر ولوحة الإدارة

واجهة المتجر مصممة بأسلوب Street Food / Neo-Brutalist حسب التصميم المرسل: أصفر وأحمر وأسود، حدود واضحة، ظلال حادة، شرائط متحركة، واستجابة للموبايل. كما تم توحيد ألوان لوحة الإدارة مع نفس الهوية.

المشروع يحتوي على:
- `index.html`: متجر العملاء، المنيو من Supabase، خيارات الأحجام والإضافات، السلة، وتسجيل الطلب في قاعدة البيانات ثم فتح واتساب.
- `admin.html`: لوحة إدارة مستقلة مع تسجيل دخول Supabase Auth، الطلبات، الأصناف، التصنيفات، الإضافات، ورسوم التوصيل/فتح أو غلق استقبال الطلبات.
- `supabase/schema.sql`: إنشاء الجداول وسياسات RLS ودالة آمنة لحساب الأسعار وحفظ الطلب.
- `supabase/seed.sql`: إدخال بيانات المنيو الأولية الموجودة في النسخة التي أرسلها المستخدم.

## الإعداد لأول مرة

1. افتح Supabase Dashboard الخاص بالمشروع، ثم افتح **SQL Editor**.
2. نفّذ محتويات `supabase/schema.sql` كاملة. المشروع يفترض أن أسماء جداول Hopa المستخدمة هنا غير موجودة سابقًا أو متوافقة مع نفس المخطط.
3. نفّذ `supabase/seed.sql` لإضافة التصنيفات والأصناف والإضافات والأسعار الأولية. راجع الأسعار ورسوم التوصيل قبل الإطلاق لأن بعض أسعار الإضافات في الكود الأصلي كانت تقديرية.
4. مفاتيح الاتصال بالواجهة موجودة داخل `index.html` و`admin.html` وتشمل عنوان المشروع والمفتاح العام Publishable Key فقط. لو غيّرت المفتاح العام، حدّثه في الملفين.
5. من **Authentication → Users** في Supabase، أنشئ حساب المستخدم المسؤول ببريد إلكتروني وكلمة مرور قوية.
6. انسخ UUID لحساب المسؤول، ثم نفّذ في SQL Editor مع استبدال المثال بالمعرّف الفعلي:

   ```sql
   insert into public.admin_users (user_id)
   values ('UUID-OF-YOUR-AUTH-USER')
   on conflict (user_id) do nothing;
   ```

7. شغّل الموقع من خادم محلي، ولا تفتحه مباشرة عبر `file://`. من داخل مجلد المشروع شغّل:

   ```bash
   python -m http.server 8000
   ```

   ثم افتح `http://localhost:8000/index.html` وللإدارة `http://localhost:8000/admin.html`.

## أمان مهم

- **لا تضع `SUPABASE_SECRET_KEY` أو أي `service_role` key داخل HTML أو JavaScript يعمل في المتصفح.** المتصفح يستخدم Publishable Key وسياسات RLS للتحكم في الوصول.
- المفتاح السري الذي نُشر في المحادثة يجب تدويره/إلغاؤه من Supabase قبل الإطلاق. لا ترسل المفتاح الجديد لأي أحد ولا تضفه إلى الملفات.
- لا تجعل سياسات قراءة `orders` و`order_items` عامة. المخطط يقيّدها بالمستخدمين المضافين إلى `admin_users`، بينما إنشاء الطلبات العامة يمر عبر `create_hopa_order` التي تحسب الأسعار من صفوف المنتجات والإضافات على قاعدة البيانات.
- الدفع في هذه النسخة عند الاستلام/التأكيد عبر واتساب فقط؛ لا يوجد تكامل بوابة دفع إلكتروني.
- المفتاح العام وURL المشروع ظاهران في الموقع بطبيعة الاستخدام. لا يحتوي المشروع على مفتاح Secret.

## حالة التنفيذ

- `index.html` يستخدم كتالوج Supabase، ويحسب العرض في المتصفح للمعاينة فقط، بينما دالة `create_hopa_order` تحسب الأسعار النهائية وتخزن الطلب على قاعدة البيانات.
- `admin.html` ما زالت منفصلة وتعتمد Supabase Auth وصلاحية `admin_users`، مع إدارة الأصناف والتصنيفات والإضافات والطلبات وإعدادات المطعم.
- تم فحص صياغة JavaScript محليًا، لكن لم يتم تنفيذ طلب حي على قاعدة بياناتك ولم يتم نشر الموقع.
- لم نثبت وجود عرض 399 جنيه أو فروع خارج ميت فضالة؛ لذلك تم استبدال المعلومات غير المؤكدة برسالة عامة وبعنوان المطعم ورقمي الهاتف الموجودين في الإعدادات.

## اختبارات قبل النشر

1. افتح `index.html` وتأكد من ظهور الأصناف من قاعدة البيانات.
2. أنشئ طلبًا تجريبيًا وتأكد من ظهور سجل في `orders` وسجلات مرتبطة في `order_items`.
3. جرّب تسجيل دخول بحساب غير مضاف إلى `admin_users` ويجب رفض الوصول الإداري.
4. غيّر حالة طلب من لوحة الإدارة وتأكد أنها تظل بعد تحديث الصفحة.
5. غيّر رسوم التوصيل وحالة فتح المطعم ثم أعد تحميل متجر العملاء للتحقق.
6. راجع رقم واتساب المطعم، العنوان، الأسعار، ورسوم التوصيل قبل استقبال طلبات حقيقية.
